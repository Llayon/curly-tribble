# ADR 0011: Surface Gameplay Map as Navigation & Buildability Authority (Milestone M6)

## Context

After ADR 0010 (M5.1), production rendering flows exclusively through the
validated `SurfaceTerrainBake`, but two subsystems still relied on legacy
`MapData`-derived data:

1. **Navigation** (`src/map/navigation/`) ran A* over a static grid built
   during `spawn_map_internal` from `TileData.elevation` and an approximate
   steepness gate. That grid was non-deterministic with respect to the solved
   surface: `follow_path` lerped Y from legacy elevations while the baked
   mesh rendered the solved heights, so pawns could walk "under" or "through"
   the visible terrain. The static grid also forced `generation/terrain.rs`
   to depend on the navigation module and had to be cleared/rebuild on every
   regeneration.
2. **Buildability coloring** (`tile_color`) re-derived an approximation
   (`is_too_steep` + `allows_buildings()`) inside the mesh generator, giving
   the editor a "green overlay" that did not match the validated surface and
   could not account for cliff seams or solved neighbor steps.

The solution is a solved-surface policy layer: one authoritative
`SurfaceGameplayMap` derived from the M5 solved height domain, consumed by
both pathfinding and buildability coloring.

## Decision

1. **`SurfaceGameplayMap` is the single navigation/buildability authority**:
   - Derived in three stages from the solved surface: pure-geometry metrics
     (`derive_surface_metrics` from `SurfaceTopology` + `SurfaceTerrainBake`,
     no `MapData`), edge metrics (seams and solved height deltas), and a
     policy compile (`compile_surface_gameplay`) that maps cells to
     walkable / `movement_cost` (20/50/80) / buildable and edges to
     traversable / `CliffSeam` / `HeightStep`.
   - `compile_surface_gameplay` may read only the *classification* fields of
     `TileData` (`OceanState`, `TerrainType`) — never `.elevation`.
   - Regenerated by `regenerate_surface_gameplay` in `FixedUpdate`, gated on
     a successful bake, with a strict input fingerprint (bake stamp + tile
     classification + config) and a no-retry record.

2. **A* routes through gameplay** (`compute_astar_path`):
   - New signature: `(&SurfaceGameplayMap, &HashMap<IVec2, u8> dynamic,
     start, target, radius)` — the dynamic grid holds only `NavObstacle`
     overlays; all static costs come from gameplay cells.
   - Waypoint Y comes from `gameplay_center_world_pos` (solved center height
     × `MAX_HEIGHT` + `AGENT_HEIGHT`), the ONLY place `MAX_HEIGHT` meets
     gameplay data (`surface_gameplay/world.rs`).
   - `MapData` and `grid_to_world` are removed from navigation; the static
     `NavigationMap` grid is retired from generation
     (`rebuild_navigation_grid` deleted), so `generation/terrain.rs` no
     longer depends on navigation.

3. **Buildability coloring is policy-external**:
   - `tile_color` takes a `buildable: bool`; the lookup happens lazily inside
     `bake_vertex_color` only when the build-area layer is visible (Sediments
     phase): `gameplay.cells.get(&coord).ok_or(MissingGameplayCell)?.buildable`.
   - Fail-closed: a land tile missing from the gameplay layer is a render
     error, not a silent fallback.
   - `SpawnGlobalTerrainCommand` carries the `SurfaceGameplayMap`; the legacy
     `create_global_map_meshes` keeps an approximate gate documented for
     removal once the bake path is the only mesh path.

4. **Fail-closed rebuild gating**:
   - `handle_rebuild_mesh` runs only when `TerrainBakeGenerationOutcome ==
     Success` AND `SurfaceGameplayGenerationOutcome == Success`; otherwise
     the previously rendered terrain stays intact.
   - `validate_mines` accessibility check routes through `compute_astar_path`
     on gameplay data and fails closed (inaccessible) when the gameplay layer
     is not `Success`.

5. **Architecture enforcement** (4 new guards):
   - `test_navigation_decoupling`: navigation production forbids `MapData`,
     `TileData`, `TerrainType`, `OceanState`, `MAX_HEIGHT`, legacy topology,
     `.elevation`, mesh/rebuild types.
   - `test_surface_gameplay_decoupling`: core (types/metrics/edges) is pure
     geometry; compiler/runtime may read classification fields only; world.rs
     is the only world-space (MAX_HEIGHT) adapter.
   - `test_generation_terrain_decoupling`: generation must not touch
     navigation types at all.
   - `test_production_terrain_routes_through_gameplay`: systems.rs gates on
     gameplay `Success`, feeds the map into the command, and bake.rs fails
     closed with `MissingGameplayCell`.

6. **Test proof**:
   - Canonical 144-case gameplay matrix (6 shapes × 3 profiles × 8 seeds):
     full pipeline to `compile_surface_gameplay`, cell/edge policy
     invariants, stats consistency, A* smoke over pure gameplay data.
   - Rewritten `tests/navigation_tests.rs` (un-ignored): straight path,
     U-obstacle detour, blocked-target-with-radius (hex-geometry aware), and
     unreachable — all against gameplay layers without `MapData`.
   - Overlay regression test: green (buildable) / red (blocked) / blue
     (ocean) colors come from `SurfaceGameplayMap` cells.

## Consequences

- Pawn pathfinding and editor buildability overlay now share one solved,
  replayable source; the mesh, path Y, and buildability can no longer
  diverge.
- Generation no longer builds or owns a static navigation grid; `NavObstacle`
  overlays remain the only dynamic input to pathfinding.
- `MapData.elevation` is eliminated from navigation and coloring; the legacy
  elevation-based approximation survives only in the test-only legacy mesh
  generator, documented for removal.
- `handle_rebuild_mesh` is double-gated (bake + gameplay): a failure in
  either layer preserves the last rendered frame.
- M6 completes the ADR 0009/0010 vision: height domain (M5) → bake (M5.1) →
  gameplay policy (M6) as the three-tier authority stack for geometry,
  rendering, and simulation.
